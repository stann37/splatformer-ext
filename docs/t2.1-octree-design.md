# T2.1 — Adaptive-Octree PTV3: design

## The central observation (paper framing)

PTV3's `SerializedPooling` (Pointcept `point_transformer_v3m1_base.py:341`) pools by

```python
code = point.serialized_code >> pooling_depth * 3   # go up N octree levels
torch.unique(code[0], return_inverse=True)           # group by parent cell
```

Right-shifting a Morton/Hilbert code by 3 bits **is** moving to the parent octree cell.
So serialized pooling is *already* octree pooling — restricted to the degenerate case
where every point sits at the same depth (`bit_length(grid_coord.max())`, = 9 for
SplatFormer's G=384) and pooling moves all points up uniformly.

**Our method: generalize the implicit uniform octree to an importance-weighted
adaptive octree.** Three new degrees of freedom:

1. **`D_max` (finest depth)** — points are serialized at depth `D_max=12` (4096³ cells)
   instead of 9 (512³). Dense regions stay distinguishable deeper into the network.
   (Motivation: 13.9% of Gaussians collide at G=384 on a typical scene;
   `scripts/voxel_collisions.py`.)
2. **Weighted leaf depths** — per point, leaf depth `d_i` = smallest depth at which the
   weighted point count of its cell ≤ K. Weights default to 1 (pure density);
   T3.1 plugs visibility-derived importance in here. Low-importance clusters merge
   *early*; high-importance regions keep distinct tokens *longer*.
3. **Depth schedule `T_s`** — per encoder stage, every token pools to depth
   `t_i = min(d_i, T_s)` (replaces uniform stride-2).

**Strict-generalization property** (the key ablation/sanity check): with
`K=1, weights≡1, D_max=9, T=(9,8,7,6)`, grouping is *exactly* the baseline's.
Proof sketch: points sharing a cell at depth T_s have alone-depth > T_s, so they pool
at the T_s prefix (same key); points alone at T_s are singletons either way.

## Where adaptivity actually bites

With K=1/uniform weights, adaptive grouping ≡ uniform grouping (see above). The wins
come from:
- `D_max=12 > 9`: stage-0 serialization order and first-stage grouping distinguish
  co-located Gaussians that G=384 conflates (dense-region detail).
- `K>1` with importance weights: background/low-visibility clusters of ≤K effective
  weight merge at their (shallow) leaf depth even when `T_s` is fine — token budget
  reallocates from background to foreground. **This is the unbounded-scenes mechanism**
  (with T1.3 contraction: background is dense-in-contracted-coords but low-importance).

## Key mechanics (all grounded in Pointcept internals)

### Group keys (pooling)
Depth-tagged to avoid aliasing across mixed depths:
```
morton_i = octree_code_i                  # batch-free, full D_max bits
prefix_i = morton_i >> 3*(D_max - t_i)
key_i    = batch_i << (3*D_max + 5)  |  prefix_i << 5  |  t_i
```
Tokens merge iff same batch, same depth tag, same prefix. Tokens at different
depths never alias (depth in low 5 bits). 3*12+5 = 41 bits + batch ≤ 63 ✓.

### Sort codes (attention) — recomputed per stage at a COMMON depth
Naively sorting variable-depth prefixes destroys spatial locality (short prefixes are
numerically small → all coarse tokens sort first). Instead, per stage s, re-encode all
tokens on the 2^{T_s} grid using each cell's **center-on-T_s-grid**:
```
grid_coord_stage = prefix_i << (T_s - t_i)  |  (1 << (T_s - t_i - 1) if t_i < T_s else 0)
serialized_code  = encode(grid_coord_stage, batch, depth=T_s, order=...)  # all 4 orders
```
Coarse and fine tokens then interleave correctly along the curve.
Uniqueness: token cells are spatially disjoint, so center coords on the T_s grid are
unique across depths (a collision would imply one token's cell contains another's).

### CPE / sparsify coords
`Block.cpe` is a 3³ SubMConv3d over `grid_coord` — neighborhoods must be at distance 1
on the stage grid. Use the same `grid_coord_stage` as above (sparse_shape = 2^{T_s}).
Degenerate case reproduces baseline coords exactly (all t_i = T_s ⇒ center = prefix).
Stage 0 keeps per-Gaussian coords at D_max (co-cell duplicates tolerated — the
baseline already feeds duplicate grid_coords to spconv at G=384).

### Unpooling — unchanged
`SerializedUnpooling` only consumes `pooling_parent` + `pooling_inverse`, which our
pooling produces identically. Zero changes to the decoder path.

### Leaf-depth assignment (vectorized, ~D_max unique() calls)
```
for d in 0..D_max:  counts_d[i] = scatter_add(w, unique_inverse(prefix at d))
d_i = min{ d : counts_d[i] ≤ K }   (else D_max)
```
Monotone in d, so a single pass suffices. ~13 × unique on 100k int64 — negligible cost.

## Stage-0 tokens = Gaussians (not leaves)
Matches baseline (co-cell points stay separate tokens at stage 0); first pooling merges
to `min(d_i, T_1)`. Preserves per-Gaussian identity in early attention.

## Octree features (input augmentation)
Per-Gaussian, concatenated to the backbone input feature (v1; head-side injection is an
ablation): normalized leaf depth, intra-leaf position (3), log leaf count, log leaf
size — 6 dims. Rationale: density-aware positional encoding; co-leaf Gaussians get
distinguished by intra-leaf position even after merging.

## Defaults (gin-configurable)
- `D_max=12`, `leaf_K=1.0`, `depth_schedule=(12, 9, 8, 7)`, weights=1 (until T3.1)
- Schedule rationale: T_1=9 ≈ baseline's stage-0 resolution → stage-1 token counts
  comparable to baseline stage-0→1 (measured: 40k cells at depth 9 for 44k points).

## Validation plan
1. **Unit**: depth assignment correctness on hand-built cases; key uniqueness;
   center-coord uniqueness on random clouds.
2. **Degenerate equivalence**: K=1, D_max=9, T=(9,8,7,6) → grouping/order identical to
   baseline `SerializedPooling` on real scene data (assert same clusters per stage).
3. **Smoke**: forward+backward on a real test-set scene; token counts per stage logged.
4. **Training**: short run on train subset (uniform vs adaptive), then full Objaverse-OOD.
5. **Win condition** (with T1.3): beat 21.68 PSNR on the paper's MVImgNet protocol.

## Compute notes
Stage-0 cost identical to baseline (same N tokens, same channels). Stage 1+ has ≥
baseline token counts (finer T_s) → ~1.5–2× total. Flash attention patches (1024) keep
attention linear-ish in tokens. Sparse shapes up to 4096³ are fine for spconv (hashed).
